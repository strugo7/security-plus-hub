# Lesson: Security Controls
**Module:** 1.1

## Introduction: The Importance of Security Controls
In the IT world, there are many security risks that we need to prepare for. Attackers are constantly looking for ways to gain access to our systems, and we must find different ways to prevent this. We rely on Security Controls to monitor, alert, and recover from attacks. The goal of these controls is not only to protect data, but also to protect physical systems, buildings, people, and any other asset in the organization. Proper use of controls allows us to:
1. Prevent incidents from occurring in the first place.
2. Minimize the impact of incidents that do occur.
3. Limit the damage in case someone successfully penetrates the computing environment.

## 1. Categories of Security Controls
It is customary to divide security controls into four broad categories. Understanding these categories is essential for managing a multi-layered defense.

**A. Technical Controls**
These are controls implemented using technological systems.
• *Explanation:* Using hardware or software to enforce security.
• *Examples:*
    ◦ A system administrator defining policies within the Operating System to allow or block certain functions.
    ◦ Firewalls.
    ◦ Antivirus software.

**B. Managerial Controls**
These controls refer to the policies and procedures that dictate how people should manage their computers, data, and systems.
• *Explanation:* Creating formal security policy documents and standard operating procedures.
• *Implementation:* These controls are often embedded within the organization's security policy documents or as part of daily Standard Operating Procedures (SOPs).

**C. Operational Controls**
Unlike using technology, operational controls rely on people to implement security.
• *Examples:*
    ◦ Placing Security Guards at the workplace.
    ◦ Conducting monthly training sessions ("Lunch and Learns").
    ◦ Hanging posters or running Awareness Programs to explain best practices to employees.

**D. Physical Controls**
As the name implies, these are controls that limit physical access to a building, a room, or a device.
• *Examples:*
    ◦ Fences and locks to keep people out.
    ◦ Badge readers to limit access into certain areas within a building.

## 2. Control Types (Functions)
Within the categories mentioned above, controls can perform different operational functions depending on their objective.

**A. Preventive Controls**
• *Definition:* A control that restricts access to a specific resource.
• *Practical Context (by categories):*
    ◦ Technical: A Firewall Rule that blocks access to a part of the network.
    ◦ Managerial: An Onboarding Policy that defines access processes for new hires.
    ◦ Operational: A guard station performing ID checks (an action performed by a person).
    ◦ Physical: A door lock physically preventing entry into a room.

**B. Deterrent Controls**
• *Definition:* A control that does not necessarily prevent access, but is designed to discourage the attacker or make them "think twice" before executing the attack.
• *Practical Context (by categories):*
    ◦ Technical: A Splash Screen displaying a security warning and restricting unauthorized users when an application starts.
    ◦ Managerial: The threat of a Demotion or termination in case of access to forbidden information.
    ◦ Operational: A reception desk at the entrance greeting every person who enters (creates a sense of visibility).
    ◦ Physical: Warning signs indicating the consequences of entering the facility.

**C. Detective Controls**
• *Definition:* A control that identifies, and sometimes alerts, when a breach has occurred. It does not prevent access, but records and notifies about it.
• *Practical Context (by categories):*
    ◦ Technical: System Logs detailing everything going on in the systems.
    ◦ Managerial: Periodic review (daily/weekly) of Login Reports.
    ◦ Operational: A person patrolling the property looking for signs of a break-in.
    ◦ Physical: Motion Detectors automatically alerting to movement in an area that should normally be empty.

**D. Corrective Controls**
• *Definition:* An action taken after an incident has been detected. Its goal is to reverse the impact of the incident or allow business operations to continue with minimal downtime.
• *Practical Context (by categories):*
    ◦ Technical: Restoring from Backups after a Ransomware attack that encrypted data.
    ◦ Managerial: A policy requiring the reporting and alerting of unusual security incidents.
    ◦ Operational: Contacting Law Enforcement after a physical breach (e.g., someone jumping a fence).
    ◦ Physical: Using a Fire Extinguisher to stop the spread of a fire.

**E. Compensating Controls**
• *Definition:* A control used when a security event has occurred or a vulnerability exists, but you do not have the resources or means to completely resolve it immediately. It serves as a temporary or alternative mitigation.
• *Practical Context (by categories):*
    ◦ Technical: Blocking traffic via a firewall rule instead of immediately patching a vulnerable application.
    ◦ Managerial: Implementing a separation of duties between different individuals.
    ◦ Operational: Requiring multiple security staff to work simultaneously so no single guard has complete access.
    ◦ Physical: Using a power generator to compensate for a main power outage.

**F. Directive Controls**
• *Definition:* Considered a relatively weak security control because it directs someone to do something more secure, and requires the user to make a decision to comply with it.
• *Practical Context (by categories):*
    ◦ Technical: A policy requiring users to store sensitive information in a protected and encrypted folder (the user must decide what is sensitive and manually perform the action).
    ◦ Managerial: Compliance Policies defining proper processes.
    ◦ Operational: Conducting security Training Users.
    ◦ Physical: A sign on a door stating "Authorized Personnel Only". There is no lock, only a visual directive not to enter.

## Executive Summary
Security Controls are our primary tools for monitoring, alerting, and recovering from attacks. We classify them into four main categories: Technical (hardware/software), Managerial (policies and procedures), Operational (people), and Physical (tangible barriers). Within these categories, the controls perform different functions: Preventive to stop access (e.g., a firewall); Deterrent to discourage attackers (e.g., warning signs); Detective for identification and logging (e.g., system logs); Corrective to restore after an incident (e.g., backups); Compensating as an alternative/temporary solution (e.g., a backup generator); and Directive to guide safe behavior (e.g., compliance procedures and user training). Choosing the right controls varies between organizations and evolves as technology changes.
